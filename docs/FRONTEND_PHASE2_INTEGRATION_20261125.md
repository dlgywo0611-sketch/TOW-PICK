## Mock 및 미구현 경계

- 알림 센터 목록과 읽음 상태는 Mock/이 기기 저장이다.
- OUR PET 레벨·경험치·성장 상태는 Mock이다.
- 표시 이름 변경은 이 기기 저장이다.
- n8n/Gmail 실제 발송은 미구현이며 화면에서 발송 완료로 표시하지 않는다.
- PET DOCK 물리 장치 연결은 실제 장치가 있는 PC에서 추가 검증해야 한다.

## 발견 및 조치

- 추천 실패 직후 재추천은 잠겼지만 조건 입력이 활성 상태로 남는 문제를 실제 브라우저에서 발견했다.
- 프론트의 추천 시도 상태를 조건 편집 가능 여부에도 반영하고 회귀 테스트를 추가했다.
- 현재 `DecisionDetailRead`에는 추천 시도 여부가 없어 다른 계정이나 새로고침 직후에는 서버 상태를 화면이 먼저 알 수 없다. 백엔드에 읽기 전용 `recommendation_attempted: bool` 필드 추가를 요청한다. 현 백엔드는 실제 수정·재추천 요청을 409로 차단하므로 정책 자체는 유지된다.
- 프론트는 `recommendation_attempted`가 응답에 추가되는 즉시 조건 수정·재추천 잠금과 수동 후보 안내에 사용하도록 호환 처리를 완료했다. 현재 백엔드 응답에는 필드가 없어 새로고침·상대방 계정 지속 잠금의 UI 검증은 보류한다.

## 최종 통합 및 병합 순서

- 최신 `origin/main`의 n8n 모의 스케줄러 문서를 반영했다.
- PR #32의 PET DOCK BLE Notify 코드를 가져오면서 기존 USB·BLE 연결 해제, 재연결, 오류 표시 기능을 유지했다.
- 기존 PR과 브랜치는 삭제하거나 수정하지 않았고 `main`에 직접 push하지 않았다.
- 가장 안전한 순서는 기존 프론트 스택 PR을 앞에서부터 병합한 뒤, PR #32와 최종 수정 브랜치를 마지막에 병합하는 것이다. 최종 수정 PR은 이전 스택 전체와 PR #32 커밋을 모두 포함하므로, 선행 PR이 모두 병합된 후 GitHub의 변경 파일이 최종 수정분만 남는지 다시 확인한다.
- 실물 USB·BLE는 주연님 PC에서 최종 병합 전에 공동 검증한다.
