## 1. 확인 범위와 제한

### 확인한 근거

- 현재 저장소와 `docs/`의 기획·설계 문서
- 현재 `main` 및 Git 전체 이력
- GitHub merge commit에 기록된 PR 번호
- 현재 브랜치의 미커밋 문서 목록
- 기존 자동 테스트와 하드웨어 검증 상태를 정리한 문서

### 실제 Notion에서 확인·반영한 내용

- Notion 연결 확인
- 기존 WBS 57개 확인
- WBS 데이터베이스에 `MVP 범위`, `검증 상태`, `증빙 경로`, `대행 기록` 속성 추가
- 1.1.3과 1.2.5에 문서 완료 및 이효재 대행 기록 갱신

### 아직 반영하거나 확인하지 못한 내용

- 나머지 누락 작업의 상태·완료 기준·증빙 링크 갱신
- 필수 칸반·담당자·주차·P0·검증 대기 보기 전체 설정 확인
- R01~R10 리스크 행 등록 및 WBS relation 연결
- 팀원 계정의 보기·링크 접근 확인과 최종 screenshot/export

신규 리스크 데이터베이스 생성은 Notion 무료 블록 한도로 차단됐다. 로컬 작업 폴더와 Git 이력에는 기존 WBS export가 없으므로, 확인된 57개 외의 과거 항목 수나 변경 전 상태는 추측하지 않는다.

### 업데이트 원칙

- 아래 표는 **확인된 기존 WBS 행에 적용하거나 남은 반영을 관리하기 위한 변경안**이다.
- WBS ID를 새로 만들거나 변경하지 않는다.
- 주담당자와 마감일은 기존 값을 유지한다.
- 대행 작업은 주담당자를 바꾸지 않고 협업자·대행 기록에 추가한다.
- 실제 변경 전 상태를 확인하지 않은 행은 추측하지 않고 `미확인`으로 표시한다.
- 같은 WBS ID 행이 이미 있으면 신규 행을 만들지 않는다.
- 문서 WBS의 기능 완료와 산출물의 GitHub 반영 단계를 별도 속성으로 관리한다.

## 4. 증빙 링크 등록 원칙

- `main` 반영 문서는 PR 번호와 merge commit을 함께 기록한다.
- 현재 브랜치의 미커밋 문서는 commit 전 임시 로컬 경로로만 표시하고, PR 생성 후 PR 링크로 교체한다.
- 로컬 절대 경로를 Notion 공동 증빙 링크로 사용하지 않는다.
- GitHub 반영 전에는 `문서 작성 완료 / GitHub 반영 대기`로 표시한다.
- 기능 PASS에는 `TEST_EVIDENCE_RULES.md`의 증빙 규칙을 적용한다.
- 하드웨어·사용자 테스트·대용량 영상은 접근 가능한 외부 공유 링크와 manifest를 연결한다.

## 5. WBS 1.2.6 현재 판정

로컬 상태 업데이트안, Notion 설정 가이드와 리스크 관리표를 작성했다. 실제 Notion에서는 WBS 57개를 확인하고 관리 속성 4종과 1.1.3·1.2.5의 문서 완료·대행 기록을 반영했다. 그러나 나머지 누락 작업, 필수 보기 전체와 R01~R10 리스크표는 아직 반영되지 않았고 신규 리스크 데이터베이스 생성은 무료 블록 한도로 차단됐다.

따라서 WBS 1.2.6은 **PARTIAL — 일부 Notion 반영 / 잔여 설정 및 리스크표 반영 대기**로 판정한다.

완료 전 필요한 확인:

1. 확인된 57개 행의 WBS ID 중복·누락 검수
2. 기존 담당자·마감일과 상태 옵션 보존 확인
3. 1.1.3·1.2.5 외의 위 변경표를 기존 행에 적용
4. 필수 보기 7개 생성 또는 기존 보기 검수
5. 무료 블록 한도 해소 또는 기존 DB 재사용 후 R01~R10 리스크 행 등록
6. 담당자·마감일·링크·검증 상태 확인
7. 팀원이 같은 결과를 볼 수 있는지 확인하고 screenshot/export 확보
