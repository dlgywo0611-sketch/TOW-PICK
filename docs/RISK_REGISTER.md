## 1. 평가 기준

| 등급 | 발생 가능성 | 영향도 |
|---|---|---|
| 높음 | 현재 미구현·반복 발생·일정 내 발생 가능성이 큼 | P0 시연 실패, 보안·데이터·장비 안전 또는 전체 일정에 직접 영향 |
| 중간 | 조건에 따라 발생 가능 | 일부 WBS 지연 또는 P1 시연 품질 저하 |
| 낮음 | 현재 징후가 적고 우회 가능 | 국소적 수정으로 회복 가능 |

우선순위:

- `Critical`: P0 완료 또는 안전을 직접 차단
- `High`: 핵심 품질·데이터 무결성·일정에 큰 영향
- `Medium`: P1 또는 증빙 완성도에 영향

다음 확인일은 기존 WBS 마감일을 변경하는 값이 아니라 **리스크 재검토 제안일**이다. 실제 Notion 반영 시 팀 일정과 대조한다.

## 4. 운영 규칙

- 매일 또는 다음 확인일에 가능성·영향도·상태·대응책을 갱신한다.
- 새 리스크는 기존 WBS ID를 검색한 뒤 관련 WBS에 연결한다.
- `Blocked` 리스크는 차단 원인, 필요한 결정자와 해제 조건을 반드시 기록한다.
- `Mitigated`로 닫을 때 대응 실행 증빙과 잔여 위험을 남긴다.
- 구현 코드 존재나 PR 병합만으로 리스크를 닫지 않는다.
- R01~R04와 R10은 P0 칸반과 검증 대기 보기에 함께 노출한다.
- 대행 작업은 원 주담당, 대행자, 사유와 검수자를 분리 기록한다.

## 5. Notion 반영 상태

Notion 연결과 기존 WBS 57개는 확인했지만, 무료 블록 한도로 신규 리스크 데이터베이스 생성이 차단되어 이 표는 실제 Notion에 등록되지 않았다. 한도 해소 또는 기존 데이터베이스 재사용 방식을 결정한 뒤 R01~R10을 ID로 중복 검사하고 신규 생성 또는 기존 행 갱신을 선택한다.
