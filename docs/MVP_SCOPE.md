# OURVERSE 3.0 서비스 목표 및 MVP 범위

- WBS: 1.1.1
- 확정일: 2026-11-24
- 프로젝트명: OURVERSE 3.0
- 핵심 서비스: TWO-PICK
- 핵심 개념: 커플 공동 의사결정 서비스

## 1. 서비스 목표

OURVERSE 3.0은 연인·부부가 서로의 조건과 취향을 존중하면서 함께 결정을 내릴 수 있도록 돕는 커플 공동 의사결정 웹서비스다.

핵심 서비스인 **TWO-PICK**을 중심으로 두 사용자가 각각 로그인하고, 조건을 입력하고, 후보를 확인한 뒤 동일한 최신 후보를 각각 승인해야 최종 결정이 확정되는 구조를 사용한다.

**OUR PET**과 **SMART COUPLE CARE**는 TWO-PICK의 사용 경험을 확장하는 보조 기능으로 구성한다.

## 2. 범위 구분

| 우선순위 | 범위 | 목표 |
|---|---|---|
| P0 | TWO-PICK | 두 사용자의 공동 의사결정 핵심 흐름 완성 |
| P1 | OUR PET + PET DOCK + SMART COUPLE CARE | 핵심 흐름과 연결되는 최소 시연 구현 |
| P2 | 커뮤니티·추천 고도화·3D·추가 자동화 및 하드웨어 | P0/P1 안정화 이후 확장 |

이 문서는 구현 우선순위와 완료 기준을 확정하는 산출물이다. 특정 기능이 P0 또는 P1에 포함된다는 사실만으로 현재 구현이 완료됐음을 의미하지 않는다. 실제 구현 및 검증이 끝난 기능만 완료로 판정한다.

## 3. P0 — 반드시 완성해야 하는 핵심 기능

### TWO-PICK

- 회원가입 및 로그인
- 두 개의 독립 사용자 계정 사용
- 커플 초대 코드 생성 및 참여
- 커플 연결 상태 확인
- 사용자별 조건 입력
- 상대방의 비공개 세부 조건 보호
- 두 사람의 조건을 반영한 후보 생성 또는 추천
- 후보 버전 관리
- 최신 후보만 승인 가능
- 두 사용자의 독립 승인
- 동일한 최신 후보를 두 명 모두 승인해야 최종 확정
- 구버전 승인 무효 처리
- 중복 승인 및 확정 후 재승인 차단
- 타 커플 데이터 접근 차단
- 결정 목록 및 상세 조회
- 최종 결정 기록
- 주요 오류 및 예외 상황 처리

### P0 완료 기준

두 개의 서로 다른 사용자 계정으로 다음 흐름을 실제 웹에서 처음부터 끝까지 재현할 수 있어야 한다.

```text
로그인
  → 커플 연결
  → 조건 입력
  → 후보 확인
  → 사용자 A 승인
  → 사용자 B 승인
  → 최종 결정 확정
  → 결과 조회
```

추가로 다음 조건을 만족해야 한다.

- 두 사용자의 승인은 서로 다른 로그인 계정에 귀속된다.
- 두 사용자가 동일한 최신 후보를 승인한 경우에만 확정된다.
- 구버전, 중복 승인, 확정 후 재승인이 차단된다.
- 다른 커플의 조건, 후보, 승인, 결정 기록에 접근할 수 없다.
- 상대방에게 사용자별 비공개 세부 조건이 노출되지 않는다.
- 주요 정상·예외 흐름을 반복 실행할 수 있다.
- 하드웨어가 연결되지 않아도 TWO-PICK 웹서비스 전체 흐름이 독립적으로 동작한다.

## 4. P1 — 최소 시연 범위

P1은 TWO-PICK P0 흐름이 안정적으로 동작한 이후 통합한다.

### OUR PET

- 커플당 가상 펫 1개
- 캐릭터 풀은 곰·토끼 2종이며, 두 사용자의 생일 월·일 숫자 합계가 짝수이면 곰, 홀수이면 토끼 배정
- 사용자 A/B 입력 순서와 무관하게 동일한 펫 배정
- 생년은 수집하지 않고 생일 원문은 상대에게 자동 공개하거나 영속 저장하지 않는 최소 수집 우선
- 곰 기본·성장, 토끼 기본·성장 이미지 총 4장
- TWO-PICK 공동결정 완료 시 경험치 지급
- 동일한 결정으로 경험치가 중복 지급되지 않도록 처리
- 기본 상태와 성장 상태 등 최소 2~3단계 표현
- 결정 기록과 펫 성장 경험 연결

### OUR PET 완료 기준

- 커플별로 하나의 펫 상태를 조회할 수 있다.
- 생일 합계 규칙으로 한 종만 결정적으로 배정되며 입력 순서가 결과에 영향을 주지 않는다.
- 가능한 경우 생일 월·일 원문이 아닌 펫 종류와 배정 규칙 버전만 영속 저장된다.
- 공동결정 1건이 확정되면 경험치가 한 번만 지급된다.
- 같은 결정의 재처리나 중복 요청으로 경험치가 다시 지급되지 않는다.
- 누적 경험치에 따라 최소 2~3개의 성장 상태를 구분해 표시한다.

### PET DOCK

- Arduino UNO 버튼 입력
- 버튼 이벤트를 USB Serial 9600 baud와 Browser Web Serial을 통해 웹에서 수신
- KEYES Bluetooth 4.0 광고명 `Meem` 연결
- BLE Service `FFE0`, Characteristic `FFE1` 사용
- Browser Web Bluetooth WRITE `R`, `G`, `B`, `X`로 RGB LED 상태 제어
- PET 상태와 LED 표시 연결

### PET DOCK 경계 및 완료 기준

- PET DOCK 버튼은 PET 이벤트를 위한 보조 입력이다.
- PET DOCK 버튼은 공동결정 승인 버튼으로 사용하지 않는다.
- 공동결정 승인은 반드시 로그인한 두 사용자가 웹에서 각각 수행한다.
- 하드웨어 연결 실패나 미연결 상태가 TWO-PICK의 로그인·조건·후보·승인·확정 흐름을 막아서는 안 된다.
- BLE 버튼 Notify는 P1 필수 범위가 아니며, USB Serial 버튼 입력으로 최소 시연한다.
- KEYES RXD 입력 전압 검증 전에는 UNO TX를 직접 연결하지 않는다.

### SMART COUPLE CARE

- 기념일 또는 일정 최소 1종 등록
- 커플 단위 일정 조회
- n8n 기반 알림
- D-1 또는 당일 알림 중 최소 하나 시연
- 테스트 계정으로 실제 알림 1회 발송

### SMART COUPLE CARE 완료 기준

- 로그인 사용자가 자신의 커플 일정만 등록하고 조회할 수 있다.
- 등록된 일정 한 건을 기준으로 n8n 워크플로가 실행된다.
- D-1 또는 당일 조건 중 최소 하나에 대해 테스트 계정으로 실제 알림 발송을 확인한다.

## 5. P2 — 시간 여유가 있을 경우 확장

다음 기능은 P0 핵심 흐름과 P1 최소 시연이 안정화된 이후에만 진행한다.

- 익명 커플 커뮤니티
- 선물 추천 기능 고도화
- 복잡한 AI 추천
- 다양한 OUR PET 아이템 및 꾸미기
- 실시간 3D 펫 렌더링
- 복잡한 펫 애니메이션
- 다수의 기념일 자동 분류
- 알림 채널 확대
- 추가 센서 및 하드웨어 기능
- BLE 버튼 무선 Notify 방식 고도화
- 서비스 운영용 관리자 기능

P2 기능 때문에 P0 기능의 구현이나 테스트 일정이 지연되지 않도록 한다.

## 6. 범위 우선순위 원칙

1. **TWO-PICK P0 완성도를 최우선으로 한다.**
2. OUR PET, PET DOCK, SMART COUPLE CARE는 P0가 안정적으로 동작한 뒤 통합한다.
3. 하드웨어는 웹서비스의 보조 장치이며 TWO-PICK의 필수 의존성이 아니다.
4. 실제 구현 및 검증되지 않은 기능은 완료로 표시하지 않는다.
5. 기능 수를 늘리는 것보다 두 사용자 공동결정 흐름의 안정성과 재현성을 우선한다.
6. 하드웨어 이벤트와 로그인 사용자의 공동결정 승인을 별도 도메인으로 유지한다.

## 7. 최종 범위 합의

- **P0:** TWO-PICK 공동 의사결정 핵심 흐름
- **P1:** OUR PET + PET DOCK + SMART COUPLE CARE 최소 시연
- **P2:** 커뮤니티·추천 고도화·3D·추가 자동화 및 하드웨어 확장

## 8. WBS 1.1.1 완료 판정

TWO-PICK의 필수 흐름과 OUR PET·PET DOCK·SMART COUPLE CARE의 최소 구현 범위를 P0/P1/P2로 구분하고, 각 우선순위의 완료 기준과 범위 제외 원칙을 확정했다.

따라서 **WBS 1.1.1 서비스 목표 및 MVP 범위 확정은 완료**로 판정한다. 이 완료 판정은 기획 범위 확정에 대한 것이며, 문서에 열거된 개별 기능의 구현 완료를 의미하지 않는다.
