## 판정 기준

- **implemented**: 현재 `main` 코드에 동작이 구현되어 있음
- **tested**: 현재 자동 테스트가 해당 동작을 직접 검증함
- **partial**: 기본 동작은 있으나 제약, 동시성 또는 테스트 보장이 부족함
- **planned**: 현재 `main`에 구현되지 않음

자동 테스트는 의존성이 설치된 환경에서 `SECRET_KEY`를 설정한 뒤 다음 명령으로 실행한다.

```powershell
python -m unittest discover -s tests -v
```

## 공동결정 상태 규칙

1. 커플에 가입한 로그인 사용자가 결정을 만들면 `open` 상태가 된다.
2. 후보가 추가될 때 해당 결정의 기존 current 후보는 비활성화되고 버전이 1 증가한다.
3. 로그인 사용자는 자신의 계정으로 current 후보에 한 번만 승인할 수 있다.
4. 구버전의 승인 기록은 보존할 수 있지만 새 버전의 승인으로 계산하지 않는다.
5. 정확히 2명의 커플 구성원이 동일한 current 후보를 각각 승인하면 결정이 `confirmed`가 된다.
6. `confirmed` 결정에는 후보 추가와 추가 승인을 허용하지 않는다.
7. Arduino 버튼이나 BLE 이벤트는 3번의 사용자 승인을 생성하거나 대체할 수 없다.

## API 예외 동작

| 상황 | 현재 응답 |
|---|---|
| 인증 정보 없음·유효하지 않음·폐기됨 | 401 |
| 결정 없음 | 404 |
| 후보 없음 | 404 |
| 다른 커플의 결정 접근 | 403 |
| 커플 미가입 상태에서 결정 생성·목록·상세 | 409 |
| 커플 미가입 상태에서 다른 결정의 후보 생성·승인 | 403 (일관성 보완 필요) |
| 닫힌 결정에 후보 생성·승인 | 409 |
| 구버전 승인 | 409 |
| 같은 사용자의 순차 중복 승인 | 409 |

## 코드와 기존 문서의 차이

검수 전 README는 공동 승인을 “다음 WBS”로 표시했지만, 현재 `main`에는 결정 생성, 후보 버전, 양측 승인, 확정, 목록·상세·승인 상태 조회가 이미 구현되어 있었다. README를 현재 상태에 맞게 수정했다.

PET DOCK Web Serial/Web Bluetooth 코드는 `origin/feat/seongbin-web-ble`의 `a60d01e`에 존재하지만 2026-11-24 검수 기준 `main`에는 병합되지 않았다. 따라서 해당 코드를 `main`의 완료 기능으로 표기하지 않는다.

## 자동 테스트 현황

2026-11-24 로컬 `.venv`에서 `python -m unittest discover -s tests -v`를 실행했으며 6건 모두 통과했다.

현재 `tests/test_decision_reads.py`가 직접 검증하는 범위는 다음과 같다.

- 로그인 필요
- 현재 커플의 결정만 최신순 목록 조회
- 타 커플 상세 접근 403
- 없는 결정 404
- 커플 미가입자의 목록·상세 409
- 후보 없는 상세 응답
- 최신 버전 표시
- 양측 순차 승인 후 confirmed 및 승인 상태 표시

구버전 승인, 중복 승인, 확정 후 재승인, 후보 생성의 타 커플 접근, 동시 승인·동시 버전 생성은 현재 자동 테스트가 직접 검증하지 않는다. 기존 기능을 다시 구현하지 않고 후속 백엔드 품질 작업으로 남긴다.
