2. 기존 WBS 항목은 57개로 확인했다.
3. WBS 데이터베이스에 MVP 범위, 검증 상태, 증빙 경로, 대행 기록 속성을 추가했다.

5. 신규 리스크 데이터베이스 생성은 Notion 무료 블록 한도로 차단됐다.
6. 나머지 누락 작업의 상태 변경, 필수 보기 전체, R01~R10 실제 등록은 아직 확인되지 않았다.

남은 반영 전에는 다음을 추가로 점검한다.

2. 기존 속성명·속성 type·상태 옵션·담당자 person 값
3. 기존 칸반·담당자·주차 보기를 재사용할 수 있는지 여부
4. `WBS_STATUS_20261124.md` 변경표의 대상 ID가 기존 행에 존재하는지 여부
5. 무료 블록 한도 해소 또는 기존 데이터베이스를 활용한 리스크표 대안

기존 행과 보기가 있으면 재사용한다. 같은 의미의 새 속성·상태·보기를 중복 생성하지 않는다.

## 2. WBS 데이터베이스 속성

기존 속성이 없을 때만 아래 속성을 추가한다. 이름보다 의미와 type을 우선해 기존 속성에 매핑한다.

| 관리 정보 | 권장 type | 필수 규칙 |
|---|---|---|
| WBS ID | Title 또는 Text | 기존 ID 유지, 중복 금지 |
| 작업명 | Title 또는 Text | 기존 작업명 유지, 승인된 변경만 반영 |
| 주담당자 | Person | 기존 담당자 유지 |
| 협업자 | Person multi-select | 대행자·협업자 기록 |
| 대행 기록 | Text | 원 담당자, 대행자, 사유, 검수자 |
| 우선순위 | Select | P0, P1, P2 |
| 상태 | 기존 Status/Select | 기존 옵션 우선 재사용 |
| 주차 | Select 또는 Number | 1~6주 기존 방식 유지 |
| 마감일 | Date | 기존 날짜 덮어쓰기 금지 |
| 완료 기준 | Text | 관찰 가능한 결과로 작성 |
| 산출물 | Files/URL/Text | 문서·화면·장비·workflow |
| GitHub/파일 링크 | URL | PR, main 파일, 외부 증빙 |
| 검증 상태 | Select | PASS, FAIL, PARTIAL, NOT TESTED |
| 증빙 단계 | Select | 로컬 작성, GitHub 반영 대기, PR 검수 중, main 반영, 증빙 등록 완료 |
| 차단 원인 | Text | 없으면 비움, 차단 시 해제 조건 포함 |
| 다음 행동 | Text | 담당자가 바로 실행할 한 단계 |
| 관련 리스크 | Relation | Risk Register 연결 |
| 최종 갱신일 | Last edited 또는 Date | 상태 update 추적 |

### 상태 옵션 매핑

기존 상태 옵션이 있으면 아래 의미에 가장 가까운 옵션을 사용한다.

| 의미 | 권장 표시 | 이동 조건 |
|---|---|---|
| 시작 전 | Backlog/예정 | 담당·완료 기준은 있으나 미착수 |
| 진행 | 진행 중 | 실제 작업 착수, 다음 행동 존재 |
| 검토 | 검토 대기 | 산출물 작성 후 검토 필요 |
| 검증 | 검증 대기 | 구현됐으나 실행 증빙 부족 |
| 차단 | 차단 | 외부 결정·안전·권한·선행 작업 필요 |
| 완료 | 완료 | 완료 기준 충족과 필요한 증빙 확인 |

문서 작성 WBS는 완료 기준이 문서 승인인 경우 완료로 둘 수 있다. 아직 GitHub에 반영되지 않았으면 WBS 상태와 별개로 증빙 단계를 `GitHub 반영 대기`로 표시한다.

## 3. 필수 보기 7개

### 3.1 전체 WBS

- 대상: 전체 행
- 정렬: WBS ID 오름차순, 마감일 오름차순
- 표시: ID, 작업명, 담당자, 우선순위, 상태, 주차, 마감일, 검증 상태
- 목적: 확인된 57개 기존 WBS 행의 누락·중복 확인

### 3.2 칸반 — 상태별

- Board group: 상태
- 카드: WBS ID, 작업명, 담당자, 우선순위, 마감일, 차단 원인
- 완료 이동 전 완료 기준과 검증 상태 확인

### 3.3 담당자별

- Board 또는 table group: 주담당자
- 협업자·대행 기록 함께 표시
- 미지정 담당과 과부하 확인

### 3.4 주차별

- Group: 주차
- Sort: 우선순위, 마감일
- 6주 일정의 선행·후행 작업 확인

### 3.5 P0 핵심 작업

- Filter: 우선순위 = P0
- Exclude: 완료 상태는 선택적으로 숨김
- 표시: 완료 기준, 차단 원인, 다음 행동, 관련 리스크

### 3.6 검증 대기 및 차단 작업

- Filter: 상태 = 검증 대기 OR 차단 OR 검증 상태 IN (PARTIAL, NOT TESTED, FAIL)
- Sort: 우선순위, 마감일
- 목적: 코드 존재와 완료 판정을 분리

### 3.7 리스크 관리표

- 대상: Risk Register 데이터베이스
- Sort: 우선순위, 다음 확인일
- 표시: ID, risk, 가능성, 영향도, 담당자, 대응책, 상태, 관련 WBS

## 4. 칸반 운영 규칙

1. 카드 생성 전 WBS ID로 검색해 기존 행을 우선 사용한다.
2. ID, 주담당자, 마감일은 승인 없이 변경하지 않는다.
3. 진행 중으로 이동할 때 담당자와 다음 행동을 반드시 입력한다.
4. 차단되면 원인, 해제 조건, 필요한 결정자를 기록하고 관련 risk에 연결한다.
5. 구현 또는 PR 병합만으로 완료로 이동하지 않는다.
6. 완료 기준이 기능 검증이면 `TEST_EVIDENCE_RULES.md`의 PASS 증빙이 필요하다.
7. 일부 단계만 성공하면 PARTIAL 또는 검증 대기로 유지한다.
8. 문서 WBS가 완료됐지만 GitHub 미반영이면 상태는 완료, 증빙 단계는 GitHub 반영 대기로 분리한다.
9. 대행 작업은 주담당자를 바꾸지 않고 협업자·대행 기록에 남긴다.
10. P2 작업은 P0 critical path를 지연시키면 착수하지 않는다.
11. 상태 변경 시 다음 행동과 최종 갱신일을 업데이트한다.
12. 완료·차단·우선순위 변경은 daily sync에서 공유한다.

### 권장 WIP 규칙 — 팀 확인 후 적용

- 개인별 진행 중 P0/P1 카드는 동시에 2개 이하를 권장한다.
- 새 작업을 시작하기 전 검토·검증 대기 카드를 먼저 해소한다.
- 24시간 이상 해제되지 않는 P0 차단은 RISK 표에 등록하고 팀장에게 공유한다.

이는 운영 제안이며 기존 팀 규칙이 있으면 기존 규칙을 우선한다.

## 5. 리스크 데이터베이스 속성

| 속성 | 권장 type | 값 |
|---|---|---|
| Risk ID | Title | R01 형식, 중복 금지 |
| 리스크 | Text | 원인과 사건을 구체적으로 작성 |
| 발생 가능성 | Select | 높음/중간/낮음 |
| 영향도 | Select | 높음/중간/낮음 |
| 우선순위 | Select | Critical/High/Medium/Low |
| 담당자 | Person | 대응 owner |
| 대응책 | Text | 예방·완화·우회책 |
| 다음 확인일 | Date | 마감일과 별개인 review date |
| 상태 | Status/Select | Open/Monitoring/Blocked/Mitigated/Closed |
| 관련 WBS | Relation | 기존 WBS 행 연결 |
| 증빙 | URL/Files | 로그·문서·PR·실물 증빙 |
| 갱신 이력 | Text 또는 page body | 결정과 상태 변경 이유 |

기존 리스크 데이터베이스가 있으면 새 DB를 만들지 않고 위 필드를 기존 속성에 매핑한다.

현재 Notion의 `검증 상태` 옵션에는 `FAIL`이 아직 등록되지 않았다. `PASS`, `PARTIAL`, `NOT TESTED`와 동일한 Select 속성에 `FAIL`을 추가하고, 실패 시나리오를 다른 상태로 대체하지 않도록 후속 설정·확인이 필요하다.

9. 다른 팀원 계정에서 보기와 링크 접근을 확인한다.
